# History responsiveness — 2026-10-01

Opening correction history previously awaited one full document read for every
translated document before replacing the editor content. Closed change details
also eagerly built every before/after diff in an operation, including imports
containing thousands of passages.

Version 0.32.2 reads parent translation/history flags from compendium indexes.
The history panel returns immediately, shows progress and permits cancellation,
navigation and closing while a read is pending. Cancellation suppresses late
responses; it does not cancel a server request already sent. Export is disabled
until all indexes have completed, so a stopped scan cannot be mistaken for a
complete history export. A failed index read remains visible and can be retried.

Only 20 operations are rendered per page. Closed details have no diff nodes;
expanded details render at most 20 passage pairs, with independent paging. Undo
still requires explicit confirmation and the existing fresh-document guards.

## Validation

- Root typecheck, build and release metadata passed.
- 559 automated tests passed; four optional local-model integration tests skipped.
- Regression tests cover cancellation during a stalled index request, late
  responses after leaving history, language filtering, no document hydration,
  lazy 1,200-passage diffs, navigation and closing in the actual editor class.
- In-app browser at `http://127.0.0.1:4175/`: actual history panel and service with
  synthetic Foundry pack/index fixtures, 1,874 documents and 25 operations. One
  operation contains 1,200 changed passages. Completed loading made one index
  request and zero full-document reads for the fixture's single pack.
- Stop and leave controls responded during a delayed index read. Late completion
  did not replace the editor. Expanding changes and moving to passages 21–40
  kept exactly 20 diff pairs. Browser console contained no warnings/errors.

This browser run is a synthetic integration harness, not a newly deployed native
Foundry world. Native compendium index refresh and network behavior still need
observation after the user updates the production module. No production module
restart or installation was performed during this task. The patch removes the
identified unbounded loading/rendering work; it does not prove that every possible
Foundry/browser freeze has the same cause.
