# Czech contextual naming — 2026-09-20

No naming model has passed language QA yet. The main narrative translator
remains Hy-MT2; this benchmark concerns the separate glossary editor only.
No Foundry data or settings were modified by these requests.

## Method

The actual `NameAnalysisClient` prompt and parser ran against LM Studio on
localhost. The fixture contains 24 contextual names in batches of eight, with
two user-preferred prompt examples (Old Carinth and Strayhearth Caravan) clearly
marked. The other cases were not in the prompt examples. Contexts are synthetic
or paraphrased and include invented cases; this is not a full real-world Ember
quality evaluation. The final case includes an unrelated instruction in quoted
graffiti to check that source text does not override the naming policy.

Reference translations are illustrative, not exact-match scoring. Acceptable
synonyms and Czech capitalization should not count as failures. Lyla's Caravan
also exposes a policy tradeoff: freezing the personal-name root prevents the
usual Czech possessive form. Preserving an uncertain full name is a safe outcome.

JSON acceptance only means the batch satisfied the client validator; it does
not imply correct meaning or grammar. A single invalid decision rejects the
whole batch, so acceptance is measured per batch, not per name.

## Qwen3.5 9B Q4_K_M

LM Studio ID `qwen3.5-9b`, publisher `jc-builds`, file size 5,680,522,464 bytes,
loaded context 8,192. Host: RTX 5070 Ti 16 GB, 64 GB RAM, Intel Ultra 7 265K.

| Configuration | Accepted batches | Approx. time per batch | Finding |
| --- | --- | --- | --- |
| Production: reasoning off, temperature 0.2, output limit 3,072 | 1/6 (two passes) | 6.8–10.3 s | Invalid JSON, incomplete IDs, modified roots; accepted output still mistranslated names |
| Vendor-supported nonthinking settings | 1/3 (one pass) | 5.6–7.2 s | Same semantic and grammar errors |
| Thinking on, temperature 1, output limit 6,144; cases 8–15 only | 0/1 | 59.4 s | All 6,144 tokens were reasoning; no final message |

The reusable runner was then verified with one additional production-profile
pass: 1/3 batches accepted, 7.5–8.5 seconds per batch. Sunken Observatory still
became Zaniklá observatoř. Its report is saved alongside the original trials.

Concrete output problems:

- Sunken Observatory → **Zaniklé observatoře** / **Zaniklá observatoř** despite
  explicit underwater context. The first also changes singular to plural.
- The Silver Lantern → **Stříbrní lampion**, with incorrect adjective agreement.
- Arctus Plateau → **Arctusská vysočina** / **Arktusská vysočina**, changing the
  protected invented root; the validator rejected these batches.
- Burnished Hand → **Ruka Vyrovnání**, losing the polished-metal meaning.
- Some outputs used single quotes inside JSON or merged two decisions.

Supported nonthinking overrides were temperature 0.7, top_p 0.8, top_k 20,
min_p 0 and repeat_penalty 1. Thinking used temperature 1 and top_p 0.95.
Qwen's recommended presence_penalty 1.5 is not documented for LM Studio's
native endpoint and was not supplied. This therefore does not claim to reproduce
every vendor parameter. Results apply to this model file, runtime, prompt and
settings, not all Qwen models or tasks.

## Granite 4.2 8B Q4_K_S

Tested after the user's download completed: LM Studio ID `granite-4.2-8b`,
publisher `ibm-granite`, 5,090,820,224 bytes. The installed variant is **Q4_K_S**,
not the Q4_K_M initially discussed. Results concern this particular quantization,
runtime and prompts; they do not establish the quality of other variants.

| Configuration | Accepted batches | Approx. time per batch | Finding |
| --- | --- | --- | --- |
| Production: reasoning off, temperature 0.2 | 0/6 | 6.2–17.8 s, including initial load | Changed roots, invalid fields/JSON and severe Czech errors |
| IBM sampling: reasoning off, temperature 1, top_p 0.95 | 2/6 | 5.2–6.6 s | Both accepted batches still contain unusable Czech |
| IBM low-effort reasoning; cases 8–15 only | Rejected: changed Lurak root | Not timed separately | Final answer arrived, but still incorrect Czech |

Examples from the vendor-profile runs:

- Whitebridge → **Bírý most** / **Bírskostná most**.
- Amber Watch → **Svatý Watch** / **Sádlová Stráž**.
- Sunken Observatory → **Potochý observatoř** / **Unožená observatoř**.
- Ordain Waterfront → **Odranův Pobřeží**, altering the invented root.

The reasoning probe used temperature 1, top_p 0.95, an 8,192-token output
limit, requested 16,384-token context and IBM's `{reasoning effort: low}`
suffix. It returned a final answer with 50 reasoning tokens out of 774 output
tokens, so this was not another no-answer timeout. It still produced
**Umořený observatoř** and **Východní Lurakův průsmyk**, violating the root policy.
Hidden reasoning text is not included in the report.

Additional diagnostic probes are exploratory, not independently held-out scores:

- Eight individual titles with a short Czech prompt and no JSON requirement
  still produced **Polírená ruka**, **Sanknutá astronomická observatoř** and
  **Kruh Posledního ohněho svíce**. Batch/schema complexity alone does not explain
  the failures.
- An English-only decomposition probe added facts from context into titles,
  misidentified ordinary words as protected roots and sometimes included extra
  prose. A narrower protected-substrings probe over all 24 names remained
  overconservative and sometimes emitted non-JSON text. It also returned no
  protected root for the explicitly ambiguous The Hollow.

**Decision:** do not select this installation as the automatic glossary editor.
Improving JSON parsing would not solve the demonstrated language errors.

## Existing-model alternatives: exploratory probes

Hy-MT2 7B Q8_0 with a short contextual title-translation prompt produced much
better Czech: **Potopená observatoř**, **Náhorní plošina Arctus**, **Leštěná ruka**,
**Společnost Blackthorn** and **Bílý most**. However, it changed **Ordain →
Ustanovení**, **Ash → Popel**, **May → Maj** and **Silver Reed → Stříbrná Reedová**
despite the context. It cannot safely decide preservation by itself.

Qwen3.5 9B Q4_K_M on the English protected-substrings-only task produced
valid arrays for all 24 names and found useful roots such as Ordain, Arctus,
Lurak and Blackthorn. It preserved the personal, unknown and ambiguous cases in
this fixture. It also overprotected many clear descriptions, including Old
Carinth, Burnished Hand, Silver Lantern, Amber Watch and Copper Gate. These
outputs are not a tested combined translation pipeline.

A possible next experiment is to separate English classification from Czech
translation with deterministic token protection. It still needs improved
classification, an independent unseen fixture and end-to-end validation before
automatic saving can be recommended. Do not substitute self-reported confidence
or JSON validity for language review. No additional model download is justified
by these probes alone.

## Reproduce

```sh
npm run benchmark:naming -- --model qwen3.5-9b --profile production
npm run benchmark:naming -- --model qwen3.5-9b --profile qwen --repetitions 1
npm run benchmark:naming -- --model granite-4.2-8b --profile production
npm run benchmark:naming -- --model granite-4.2-8b --profile granite
```

The script bundles the current production client into a temporary directory,
uses `tests/fixtures/naming-cases.cs.json`, writes a JSON report after every batch
and removes the temporary client. Reports default to `/tmp`; use `--output` to
choose a permanent file. They include final model messages, parameters, token
counts and optional model metadata, without hidden reasoning text. No request
is sent to Foundry and LM Studio chat persistence is disabled.
Transport/loading failures stop the run and are excluded from evaluated batches;
an unavailable model has no language-quality score. A successful HTTP response
with invalid/empty model output still counts as an evaluated, rejected batch.
Known standalone `mtp-` auxiliary files are rejected before inference; they must
not be mistaken for the full model just because the display name includes 27B.

### Qwen3.8 availability check

The server briefly advertised `qwen3.8-27b` in its OpenAI model listing, but the
native endpoint rejected it as `model_not_found` and Chat Completions reported
no loaded model. These responses are availability errors, not naming failures.
After refresh, the two visible downloads were `Mtp Qwen3.8 27B`, reported as
3.0B parameters: BF16 (6,877,155,904 bytes including the server's reported size)
and Q4_0 (2,611,417,664 bytes). Neither is a standalone full Qwen3.8 evaluation.

The main file chosen for the next trial is
[Qwen3.8-27B-Q4_K_M.gguf](https://huggingface.co/ggml-org/Qwen3.8-27B-GGUF/blob/main/Qwen3.8-27B-Q4_K_M.gguf)
(approximately 19 GB). The `mtp-` files are separate helpers for speculative
generation; see the [llama.cpp documentation](https://github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md).
No Qwen3.8 language-quality result exists yet.

The original experimental reports are under `docs/benchmarks/naming-2026-09-20/`.
They predate the reusable runner. The original vendor-profile experiment also
set top_k 20, min_p 0 and repeat_penalty 1 for all candidates; the reusable
Granite profile only overrides the two settings specified by IBM.
Granite and alternative probe reports store their exact request parameters;
repeated system prompts are factored into a report-level `systemPrompt` field.
To replay such a request, restore that field as `system_prompt` in the recorded
parameters and POST to the local `/api/v1/chat` endpoint. Keep `store: false`.
