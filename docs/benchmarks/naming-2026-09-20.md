# Czech contextual naming — 2026-09-20

No naming model has passed language QA yet. The main narrative translator
remains Hy-MT2; this benchmark concerns the separate glossary editor only.
No Foundry data or settings were modified by these requests.

## Method

The actual `NameAnalysisClient` prompt and parser ran against LM Studio on
localhost. The fixture contains 24 contextual names in batches of eight, with
two user-preferred prompt examples (Old Carinth and Strayhearth Caravan) clearly
marked. The other cases were not in the prompt examples. Contexts are synthetic
or paraphrased and include invented cases; this is not a full real-world Ember
quality evaluation. The final case includes an unrelated instruction in quoted
graffiti to check that source text does not override the naming policy.

Reference translations are illustrative, not exact-match scoring. Acceptable
synonyms and Czech capitalization should not count as failures. Lyla's Caravan
also exposes a policy tradeoff: freezing the personal-name root prevents the
usual Czech possessive form. Preserving an uncertain full name is a safe outcome.

JSON acceptance only means the batch satisfied the client validator; it does
not imply correct meaning or grammar. A single invalid decision rejects the
whole batch, so acceptance is measured per batch, not per name.

## Qwen3.5 9B Q4_K_M

LM Studio ID `qwen3.5-9b`, publisher `jc-builds`, file size 5,680,522,464 bytes,
loaded context 8,192. Host: RTX 5070 Ti 16 GB, 64 GB RAM, Intel Ultra 7 265K.

| Configuration | Accepted batches | Approx. time per batch | Finding |
| --- | --- | --- | --- |
| Production: reasoning off, temperature 0.2, output limit 3,072 | 1/6 (two passes) | 6.8–10.3 s | Invalid JSON, incomplete IDs, modified roots; accepted output still mistranslated names |
| Vendor-supported nonthinking settings | 1/3 (one pass) | 5.6–7.2 s | Same semantic and grammar errors |
| Thinking on, temperature 1, output limit 6,144; cases 8–15 only | 0/1 | 59.4 s | All 6,144 tokens were reasoning; no final message |

The reusable runner was then verified with one additional production-profile
pass: 1/3 batches accepted, 7.5–8.5 seconds per batch. Sunken Observatory still
became Zaniklá observatoř. Its report is saved alongside the original trials.

Concrete output problems:

- Sunken Observatory → **Zaniklé observatoře** / **Zaniklá observatoř** despite
  explicit underwater context. The first also changes singular to plural.
- The Silver Lantern → **Stříbrní lampion**, with incorrect adjective agreement.
- Arctus Plateau → **Arctusská vysočina** / **Arktusská vysočina**, changing the
  protected invented root; the validator rejected these batches.
- Burnished Hand → **Ruka Vyrovnání**, losing the polished-metal meaning.
- Some outputs used single quotes inside JSON or merged two decisions.

Supported nonthinking overrides were temperature 0.7, top_p 0.8, top_k 20,
min_p 0 and repeat_penalty 1. Thinking used temperature 1 and top_p 0.95.
Qwen's recommended presence_penalty 1.5 is not documented for LM Studio's
native endpoint and was not supplied. This therefore does not claim to reproduce
every vendor parameter. Results apply to this model file, runtime, prompt and
settings, not all Qwen models or tasks.

## Reproduce

```sh
npm run benchmark:naming -- --model qwen3.5-9b --profile production
npm run benchmark:naming -- --model qwen3.5-9b --profile qwen --repetitions 1
npm run benchmark:naming -- --model EXACT_GRANITE_SERVER_ID --profile granite
```

The script bundles the current production client into a temporary directory,
uses `tests/fixtures/naming-cases.cs.json`, writes a JSON report after every batch
and removes the temporary client. Reports default to `/tmp`; use `--output` to
choose a permanent file. They include final model messages, parameters, token
counts and optional model metadata, without hidden reasoning text. No request
is sent to Foundry and LM Studio chat persistence is disabled.

The original experimental reports are under `docs/benchmarks/naming-2026-09-20/`.
They predate the reusable runner. The original vendor-profile experiment also
set top_k 20, min_p 0 and repeat_penalty 1 for all candidates; the reusable
Granite profile only overrides the two settings specified by IBM.
